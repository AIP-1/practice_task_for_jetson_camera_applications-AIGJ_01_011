# team4 Jetson 카메라 응용 — 발표 (5분)

---

## 1. 무엇을 만들었나 (30초)

- 팀 Jetson Orin Nano Super 1대, IP 카메라 1대, USB 웹캠 2대
- 과제 1~5 기능 시험 → 과제 6에서 **재실 인원 + 근접 경고**를 한 서비스로 묶어 12시간 가동
- 결과는 숫자만 MQTT(retain)와 REST로 낸다. 운영 모드에서는 영상을 한 장도 저장하지 않는다

## 3. 설계 변수 하나로 가장 크게 달라진 것 (1분 30초)

**수신 루프: `read()` 그대로 → 최신 1장만 남기는 리더**

| 입력 | `read()` 2분 뒤 | 리더 2분 뒤 |
|---|---|---|
| 웹캠 | 0.86 s (0.8 s에서 멈춤) | 0.04 s |
| IP 카메라 (RTSP) | **약 105 s, 계속 증가** | 1~2 s |

- 같은 모델, 같은 처리 속도(약 3~5 fps)인데 화면이 1분 45초 전 것이었다
- 원인: 웹캠 드라이버는 4장만 두고 버리지만, FFmpeg RTSP는 받은 프레임을 모두 쌓는다
- 모델을 바꾸는 것보다 입력 구조가 결과를 더 크게 바꿨다

두 번째로 큰 것은 **카메라 구도**다. 통로와 직각으로 돌리자 행동 판정이 1/8 → 10/12가 됐다.

## 4. 모델이 못하는 것 (1분)

- **재실 인원은 늘 적게 센다**: 책상·앞사람에 가려진 사람이 프레임마다 사라진다. 960 + 2x2 조각, p75로도 MAE 1.4명에 그쳤다. 냉방 제어에서 빈 방 판정은 "0이 5분"으로만 쓴다
- **얼굴 방향 ≠ 시선**: 카메라 쪽으로 걸어오거나 폰을 보는 사람을 "관심 있음"으로 본다
- **스테레오는 틀린 값을 확신 있게 낸다**: 흰 벽 +5.9%, 근접 +307%. 그래서 유효 비율 게이트로 `unknown`을 따로 낸다
- **거리 오차는 예상보다 5~10배 크다**: 시차 잡음보다 보정·위치의 체계 오차가 크다

## 5. 다른 팀이 쓰는 법 · 남은 일 (1분)

```bash
mosquitto_sub -h <JETSON_IP> -t 'team4/t6/#' -v
```
